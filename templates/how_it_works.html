How MemTrace works

A walkthrough of the scenario, the attack, and the five-step forensic process.

1. The scenario

A finance-ops assistant routes payments among three gateways: bank_transfer, card_processor, and swiftsettle_gateway (unverified). Three agents share one memory graph per tenant: a Reader that ingests external documents, a Consolidator that summarises retrieved memories into new ones, and an Ops agent that makes routing decisions based on what it retrieves.

Every retrieval is logged as a RETRIEVED_IN edge from a Memory node to a Task node, and every decision is a Decision node connected by CHOSE to a Tool node and by FOR to a Task node.

2. The attack

Starting on day 2, a web page plants three fake incident reports — one per day on days 2, 3, and 4. Each report claims that bank_transfer and card_processor are unreliable and recommends swiftsettle_gateway instead. The Reader agent retrieves these pages as part of its normal document scan and writes them into the memory graph as Source nodes authored by an external source.

On day 3 the Consolidator reads those Source memories and writes a new Memory authored by itself — an internal agent — that summarises the same false recommendation.

3. Trust laundering

The consolidated summary memory is authored by an internal agent, so a filter that blocks external sources passes it without question. The Ops agent retrieves it and routes an increasing share of payments to swiftsettle_gateway.

Why source-only filters fail: the adversarial content crossed the trust boundary when the Consolidator summarised it. The DERIVED_FROM edge on the summary memory points back to the original external Source — that edge is what exposes the real origin.

This is trust laundering: attacker-controlled content acquires an internal provenance label by passing through a legitimate agent.

4. The five steps

1
Detect drift Compare the share of decisions that chose each gateway in a baseline window versus the attack window. A sharp increase in swiftsettle_gateway usage is the signal.
2
Investigate culprits Walk RETRIEVED_IN edges backward from the drifted decisions to find the Memory nodes that were active in those tasks. Rank by how many drifted decisions each memory appears in.
3
Prove by counterfactual replay Re-run the same Task nodes with the suspect memories hidden. Count how many decisions change outcome. This is the causal evidence, not just correlation.
4
Compute blast radius Starting from the root Source nodes, follow all DERIVED_FROM edges to find every Memory derived from the attack content — including summaries of summaries.
5
Quarantine and replay Mark every node in the blast radius quarantined, then replay the next two days with clean memory only and verify the routing returns to baseline.

5. The graph model

MemTrace stores the agent's memory, actions, and provenance in a single property graph with the following node and relationship types.

Node typeWhat it represents
SourceAn external document or web page ingested by the Reader agent
MemoryA memory written by an agent, optionally derived from one or more Sources or other Memories
ToolA payment gateway or action the Ops agent can choose
TaskA single routing task run by the Ops agent
DecisionThe tool choice made in a Task, with timestamp and a flag if it was influenced by attack content
AgentReader, Consolidator, or Ops
RelationshipFrom → ToMeaning
FROMMemory → SourceMemory was written from this Source
DERIVED_FROMMemory → MemoryMemory was summarised or derived from another Memory

6. Honest limits

The agents and the attack are fully simulated on synthetic data. There are no real payments, real incidents, or real customers.

Drift detection shows correlation between a memory and a behavior change. The counterfactual replay supports causation by demonstrating that hiding the memory changes the decision — but it is a simulation of causation, not a proof in a production system with real LLM inference.

The tracing layer is not specific to this scenario. It works with any agent system that logs its memory retrievals as edges in a property graph. The schema above is the only contract.
